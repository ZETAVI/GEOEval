# 客户迁移与代理商只读服务设计

Status: Proposed for #102 implementation；以下为可评审方案，当前运行时尚未提供这些接口。

## 1. 具体场景

| 场景 | 结果 |
| --- | --- |
| 小林归 A，有甲乙两个品牌与各自历史报告 | A 能查看两个品牌、完整客户版报告和完整联系方式 |
| 管理员将小林由 A 转 B | 同一账号关系变为 B，B 可查看迁移前后的全部客户版报告；A 的资料访问被撤销 |
| 管理员将小林转回公共池 | 所有代理均无该客户服务访问；客户仍自助使用产品，既有订单运营职责不改 |
| 公共客户分配 B | 只更新服务关系，不改变原始获客证据，不补记历史订单代理商 |
| A 持有旧链接或分页游标 | 每个请求重新验证当前关系，游标/地址本身不是授权 |
| 两个管理员从同一旧页面分别迁 B/C | 仅符合当前关系版本的一次修改成功，另一次提示关系已变化并刷新 |
| 迁移成功但响应丢失，管理员重试 | 返回原请求结果，不再次迁移或制造重复历史 |

管理员操作沿用账号详情，展示当前归属，选择目标代理或公共池，填写简短原因后确认。操作者和系统时间自动记录，不额外要求手填时间。迁移是当前服务责任变化，客户无额外确认/账号切换页面。

## 2. 数据与历史

演进现有 AgencyCustomerAttribution，增加关系 revision 与更新时间。无记录的历史公共客户视为公共初始状态；管理员首次分配才建立关系记录。首次来源 entryKey 保持原始证据，手动分配的历史客户允许没有获客 entryKey，不能伪造一次邀请。

复用 AgencyAudit 承接迁移事件，增加前后代理、关系版本、原因和请求标识所需字段。现有 CREATE_LINK/INITIAL_BIND 事件保留原语义，不覆盖；迁移事件不存报告正文、联系方式或钱包数据。请求标识和已提交结果用于恢复，不新建通用流程引擎。

同一客户只有一个当前服务代理或公共状态。订单/佣金有自己的不可变商业快照，本片不查询当前关系来改写历史。新旧代理看到的客户资料按当前关系判断，历史业绩权限不能转化成当前联系方式权限。

## 3. 写入事务和恢复

迁移输入限定客户 ID、目标代理 ID（null 明确表示公共池）、期望关系版本、原因、请求标识。服务端不接受客户端传来的当前代理或操作者作为事实。

事务中复核管理员资格、客户角色和目标代理当前资格，序列化该客户的关系更新，比较版本，原子更新关系并写入审计/请求结果。旧代理即使已停用仍可被替换；迁移不得顺便启用停用账号或修改其角色。

优先复用 Identity 自有账号事实读取与锁定方式；对参与账号按一致顺序锁定，避免两个管理员交叉操作的反向等待。公共初始记录不存在时也先锁客户账号，不能只锁不存在的归属行。具体 SQL 顺序在实施时对照现有账号治理和注册流程做真实并发验证，不凭图示判定无死锁。

同一请求标识、同一载荷恢复原结果；相同标识不同载荷冲突。新的请求若目标已经是当前归属则返回 unchanged，不制造迁移历史。陈旧版本不自动覆盖，也不默默重试成另一次意图。

故障发生在提交前则关系与审计一起回滚；提交后响应丢失按已保存结果恢复。纠正误迁移通过一条新的有原因迁移，保留原事件。没有“删除历史”或盲目改回旧值的补偿。

## 4. 只读接口与数据投影

建议新增专用 /agency/customers 及客户品牌/报告只读路由；管理员迁移路由属于 Agency，界面挂到既有账号详情。保留所有现有 TERMINAL_CUSTOMER 控制器的角色限制，不给整组客户 API 放行 AGENT，也不构造客户登录会话。

| 信息 | 当前归属代理商 | 原代理商迁出后 |
| --- | --- | --- |
| 完整登录手机号 | 可读；Identity 提供最小身份投影 | 不可再获取 |
| 业务联系人、业务联系电话、客户版品牌资料 | 可读；Brand 原 owner 提供 | 不可再获取 |
| 全部当前/历史客户版报告及原始采样回答 | 可读；GeoIntelligence 原 owner 提供 | 不可再获取 |
| 余额、会话/安全信息、内部提示词/日志/搜索证据 | 不返回 | 不返回 |
| 订单佣金历史 | 本片不接入，由后续商业权限单独决定 | 后续仅保留自身业绩的最小信息，不恢复联系方式权限 |

列表和每条品牌/报告请求都检查当前 AGENT 资格与客户归属。客户账号可访问状态遵守 Identity 当前治理边界；本片不借代理服务恢复已被停用的客户能力。品牌 ID、报告 ID 必须同时属于该客户，非归属数据使用统一不可访问结果，不泄露是否存在。

优先复用 BrandService 的只读方法和 EvaluationReportService 的 current/history/detail；客户报告序列化目前位于 EvaluationController 的 presentReport，可在原 GeoIntelligence owner 内提取为共同使用的投影。Agency 不能直接查询报告底表或重新生成报告。根模块显式复用同一配置下的模块实例，避免复制 provider 或引入 Identity↔Agency Nest 循环。

先获得服务端关系版本，再读取原 owner 的资料；返回前复核关系版本和代理资格，若期间发生迁移则不返回旧结果。该方法复用现有只读服务，避免为跨 owner 读取建立新事务框架。验收必须通过屏障式测试固定“读取期间迁移”的顺序，不能只测两个静态账号。

撤权的准确边界是迁移提交后的新请求不再授权；已经发送到浏览器的内容无法追溯撤回。Web 不持久保存客户详情，导航/刷新/页面重新获得焦点时重新核对；收到撤权响应或切换客户立即清除旧详情，并忽略过期请求。个性化数据 no-store，不建立跨代理缓存。列表分页也必须带当前代理过滤，不能把游标当成长期客户授权。对本页有界集合在返回前批量重核当前归属/版本并剔除撤权项；不把旧分页快照人数当成当前可访问人数。

## 5. 页面复用

管理员在已有客户账号详情里管理归属，不新增独立账号体系；代理商使用现有工作区导航，依次进入客户、品牌、报告。完整登录手机号与业务电话明确标注用途，避免误认为同一个字段。

复用 EvaluationReportView 的完整报告展示，不传 onStartNewEvaluation；客户控制器仍拒绝代理商写请求。旧客户页面在授权失效后显示“该客户当前不可访问”，不显示对方转给谁或其代理层级。不开放导出、代操作或新的运营全量客户目录。

## 6. 迁移、回退、并行边界

仅增量演进 Agency 关系/审计结构；旧获客证据保留，历史公共客户不批量补写，既有账号/品牌/报告/钱包/订单不迁移数据。先停用新增迁移/读取入口可回退，已发生的真实关系与审计保留，不能把回退当作无记录改绑。

运行时继续使用受控激活边界，不放开 A0 的生产获客禁用。购买代理/费率快照仍是独立商业激活依赖；未来购买与迁移须序列化同一客户关系边界，本片不偷偷改购买锁序或定价。

本轮仅拥有本 change 文档。实施窗口预计涉及 Agency、Identity 最小事实读取、Brand/GeoIntelligence 只读 exports/投影、Web 只读界面、schema/生成接口及测试；开始前重新核对支付/写作活跃修改，shared schema 等仍为单一 writer。复用 OrbStack 服务，独立逻辑测试数据；不新增全局依赖、容器或外部服务。

## 7. 架构评审与决策前沿

设计阶段 review 结论：ready for implementation planning；尚未证明运行时权限或并发已经成立。职责、复用与历史边界已固定，用户已确认完整手机号可见。当前最关键实现不确定性是读取与迁移并发时的响应撤销，以及首次公共关系的并发创建；这两项必须由有顺序控制的 PostgreSQL/HTTP 测试先证明，再接页面。

不需要新的 ADR 或通用权限框架。实施验收后将稳定读取/迁移语义归入 Agency Customer Service，并从 Product Definition 执行局部提取；佣金、提现和通知仍由各自 owner 激活。本片不再改已归档 A0 的需求。
