# 边界与实现设计

Agency 保有一单一笔不可改写的佣金入账，引用 Commerce 的最终结算；金额用整数分，资格/费率只取购买快照。缺配置或购买时停用不参与，开启0%、全赠送或全退仍保留零额结果。客户迁移和代理后续停用不修改旧权益，不授予额外服务访问。

Commerce 提供只读来源投影，包括原实付/赠送、实际退点分摊和最终结算；Delivery 只读投影提供当前进度和约定总额，应用层组合。预计退点使用原计算模块提取的纯来源分摊函数，实际退点继续调用同一函数并执行原钱包容量约束。佣金不自行计算退款来源，不读当前余额，不从充值页状态推导。

正式入账只读取不可变的原消费、购买快照、最终结算和实际退点；不获取钱包写锁，也不反向写履约。orderId 唯一及数据库来源校验使并发处理只产生一笔。佣金事务失败不影响已经提交的积分结算。候选由最终凭据和缺失账本派生，后台分页扫描，重启重新发现；使用现有 Worker 宿主，开关默认关闭。

预计是派生展示，不建立可变的预计资金账本；正式金额 immutable。汇总正式账本，预计按同源计算批量读取未入账订单，不再保存第二份收益总数。列表有界分页，详情只含原订单标题/编号、订单来源和金额依据，不开放客户报告/手机号/工单内容。代理读取须当前身份为有效 AGENT，数据按下单快照归属；管理员可筛选全量。跨账号页面重验，no-store，游标绑定身份及筛选。

方案比较：在订单退点事务里顺带计佣会让新模块故障影响客户权益，拒绝；消费不可变最终凭据独立入账更小且可恢复。另建通用账务引擎/代理钱包可变余额/提现冻结现在没有必要，本片只建立佣金账本。

原币值最大可能超过32位整数，账本用 bigint 分；API 用十进制字符串表示金额，前端直接格式化，不用浮点累加。按原规格半分向上取整，计算公式为 (净实付积分×费率bps+500)整除1000。

环境：独立 a110 / codex/issue-110-agency-commission，复用 OrbStack geoeval_issue100 / Redis10 的本任务合成环境；旧 a100 只读，开票 #109 Ready 未占写入窗口。没有真实资金或外部服务调用。迁移只增加本片账本/索引与来源约束，关闭 Worker 可停止新增；不以删账实现运行恢复。完成后归档，保护 PR 合并，工作树退出由最终 PR 记录。
