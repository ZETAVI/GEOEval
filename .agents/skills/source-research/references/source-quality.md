# Source Quality

## Evidence Levels

| Level | Source | Appropriate Use |
| --- | --- | --- |
| A | Official schema, API reference, standard, source, or observed runtime | Interface and capability claims |
| B | Official guides, release notes, examples, license, status page | Configuration, lifecycle, and operational constraints |
| C | Maintainer issues and discussions | Known limitations and unresolved behavior |
| D | Reputable independent engineering reports | Discovery and production experience |
| E | Search summaries, aggregators, unsourced posts | Discovery only |

## Conflict Rules

- Prefer the source that matches the exact version and product surface.
- Treat runtime evidence as account- and environment-specific, not universal.
- When official sources disagree, report the conflict and avoid a definitive claim.
- Record publication or access date for facts likely to change.

## Minimal Evidence Record

- claim;
- direct URL or runtime command;
- source level;
- version or environment;
- access date;
- implication for the decision;
- uncertainty or conflicting evidence.
